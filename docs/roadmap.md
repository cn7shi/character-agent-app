## 下一阶段的范围

阶段 4A 已实现 `TextModel` 的 OpenAI 兼容适配，不改变客户端业务接口。供应商、服务地址、模型名称和凭证通过本机配置提供。服务确定后执行阶段 4B，先验证供应商兼容程度。

重点验证真实流式返回、超时、限流、取消与供应商错误转换。真实调用需要可用的服务配置，不能把模拟测试当成真实接入已完成。工具与 Android 按后续阶段实施。

开发身份继续用于本机联调；真实登录仍需在对外使用前实施。阶段 4A 的实际验证见 [阶段报告](stage-reports/04a-model-adapter-and-secrets.md)。

## 阶段 1 记录

- 从以客户端骨架为主，调整为原生客户端与独立服务端。
- 明确 Room 是手机本地存储，服务端数据库是另一份存储，使用 API 对齐。
- 在线 Agent 首先在服务端实现，客户端保留轻量执行边界，不让同一次任务两端重复执行。
- 接口区分提交、查询、订阅和取消；事件与消息拥有稳定标识。
- 设计默认按用户和会话隔离，避免沿用原型的全局会话思路。
- 核验结果见 [阶段报告](stage-reports/01-foundation.md)。

## 验证原则

只对当前实现阶段作完成声明。源码未落地时不声称运行行为已通过；模拟服务不能替代真实模型与 MCP 验证；编译通过不能代替设备验证。

未来重点验证用户隔离、事务去重、状态恢复和工具执行边界。接口实现后导出 OpenAPI，按实际行为更新草案。
