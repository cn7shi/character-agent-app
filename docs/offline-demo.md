# 无需真实 AI 的联调流程

当前默认 `mock` 模式即可开发与演示，真实 AI 配置不是后续 Android、Room 和主题工作的前置条件。

## 两条固定回复

| 输入 | 回复 |
| --- | --- |
| `你好` | `【模拟回复】你好，我在。今天想聊些什么？` |
| `今天有点累` | `【模拟回复】那就先慢下来吧。你可以说说今天发生的事，我会陪你聊一会儿。` |

其他普通文本暂时使用第一条回复。回复依然经过真实的任务、逐段输出、消息保存、取消和事件恢复流程，不是只把示例写进页面。

## 笔记示例

用“开发角色 · 林舟”创建一个新会话，发送：

```text
记笔记：周末安排；买咖啡；看电影
```

模拟模型按固定规则拆分分号或换行，以首段前 60 字作标题，把各段转成清单。Agent 执行 `notes.save`，实际保存笔记和工具记录，然后才能回复已保存。输入前缀也接受英文冒号 `记笔记:`。

当前只有林舟的新版示例人设开放笔记能力。旧会话固定旧人设版本，不能静默增加工具权限；请新建会话体验。星禾暂不开放此能力。

接口入口：

- `GET /v1/notes`：当前用户的笔记，可用 `conversation_id` 筛选。
- `GET /v1/notes/{note_id}`：查看笔记正文。
- `GET /v1/runs/{run_id}/tool-calls`：核对本次实际调用与结果。

同一请求重试、同一工具调用重放都不会多存一份笔记。取消只能阻止尚未提交的写入，已经保存的笔记会保留；服务重启也不会重新执行工具。

## 直接运行演示

在项目根目录运行：

```powershell
backend/.venv/Scripts/python.exe backend/scripts/demo_chat.py
```

脚本运行以上两条聊天和一次笔记保存，输出实际回复及笔记正文。它使用独立临时数据库，不读取本机模型配置，不调用外部 AI，也不输出开发凭证；结束后清理临时数据。

需要让后续 Android 持续连接时，使用 `backend/run.ps1 -Dev` 启动开发服务，保持模型配置为 `mock`。该服务中的记录会保留在本机运行目录。

当前已经具备最小的工具执行循环与笔记能力。是否调用工具仍由固定规则决定，不是自主理解任务的真实模型；OpenAI 兼容适配目前仍只支持文本，真实模型工具调用和 MCP 按后续阶段接入。
