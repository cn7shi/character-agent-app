# 阶段 1 两端设计与接口草案

日期：2026 年 10 月 5 日。交付范围为架构、数据模型、接口示例与目录预留，当前没有可运行后端或 Android 应用。

## 本次完成

- 增加独立 `backend/` 与 `contracts/` 目录，明确客户端、服务端和接口文档的位置。
- 选定后端技术方向为 Python 与 FastAPI，开发阶段使用独立 SQLite；Android 保持 Kotlin、Compose 与 Room 方向。
- 明确账号、角色、独立会话、消息、任务和执行事件之间的关系，以及两端的数据归属。
- 在线任务由后端执行，客户端保留轻量协调和本地能力的接口位置，避免同一次任务在两端重复执行。
- 定义 10 项 HTTP 操作及流式事件约定，涵盖创建、查询、订阅、取消、重试去重和断线恢复。
- 增加 3 个 JSON 协议样例，并把推进顺序调整为后端与数据优先。

## 检查范围

已完成结构与样例检查，结果通过：

- 20 份 Markdown 文档中的 21 个本地链接均可定位，无空文档或编码替换字符。
- 3 份 JSON 示例与 3 个 JSON 文档代码块均可解析。
- 样例的请求内容、任务、会话与消息标识一致，消息顺序和事件序号符合约定；14 处 UUID 和 9 处 UTC 时间格式有效。
- 8 个后端预留目录均存在，全部 20 个源码或迁移占位文件为空。
- 10 项 HTTP 操作无重复。

这些检查只验证设计文件的结构和样例一致性。用户隔离、数据库事务、并发去重、断线恢复和任务取消尚未实现，不能视为运行验证通过。
