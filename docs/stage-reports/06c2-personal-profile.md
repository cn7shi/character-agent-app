# 阶段 6C2：个人资料与“我的”页面

日期：2026-10-05。继续交付实际管理功能，本阶段完成昵称、简介和资料重置；正式账号、头像上传仍待后续实现。

## 已交付

| 功能 | 实际行为 |
| --- | --- |
| 我的页面 | 新增原生导航入口，显示当前用户昵称和简介；无资料时显示空状态 |
| 首次保存与编辑 | 昵称 1–50、简介 0–500 个 Unicode 字符，去除首尾空白；真实写入服务端并缓存到手机 |
| 资料重置 | 弹窗可取消；确认仅清空昵称和简介，保留认证、角色、聊天、笔记 |
| 重启与身份隔离 | 资料持久保存，重开恢复；切换身份清除页面旧状态，本机缓存按连接隔离 |
| 失败与冲突 | 原保存/重置操作先落本机，未知结果可按原内容重试；冲突需明确读取最新资料，普通刷新不丢弃原操作 |
| 接口与主题边界 | Profile 业务模型、适配器能力声明、独立缓存逻辑与 Compose 页面分层；不依赖模型供应商 |

新增 GET/PUT `/v1/me/profile`、POST `/v1/me/profile/reset` 三项 API，共 19 项。迁移 005 新增独立 user_profiles 表；重置保留递增版本，避免旧请求覆盖新内容。Room 复用 profile/profile_write 快照种类，schema 仍为 2。资料不改变认证身份，不自动写入模型提示词。

## 限制与下一步

- 当前资料只有昵称和简介，未实现头像上传、账号注册/登录/注销、公开个人主页。
- 点击保存前的编辑仍是 ViewModel 状态，不保证进程终止后恢复；点击保存/重置后的待确认操作才持久化。首次离线且无缓存不能新建资料。
- 读取最新资料会放弃本机待确认意图，不取消已到达服务的请求；界面有说明，后续修改继续受版本冲突保护。没有后台自动同步。
- AI 继续使用固定模拟回复；真实模型、MCP、实体手机和 6B2 剩余验收未纳入本阶段完成范围。

原计划下一步进入 6C3：先交付会话改名与搜索，再逐项交付笔记编辑、删除；原型还原与多主题仍在阶段 7。
