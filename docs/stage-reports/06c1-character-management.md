# 阶段 6C1：自己的角色可以创建、编辑和删除

日期：2026-10-05。按用户反馈，优先推进可直接操作的管理功能，不再让完整设备验收成为所有功能的前置条件。本阶段实现角色管理，下一步是个人资料和“我的”页面；个人资料尚未实现。

## 已交付

| 功能 | 实际行为 |
| --- | --- |
| 创建角色 | 角色页进入原生表单，填写名称、简介、人设，可开启笔记能力；真实写入后端，再在手机缓存 |
| 查看与编辑 | 自建卡片显示“仅自己可见”，可读取完整人设并修改；内置角色仍可聊天但没有编辑/删除入口 |
| 删除角色 | 先确认，可取消；确认后从列表移除，不能再建新会话，旧聊天、草稿和笔记保留 |
| 开始聊天 | 自建角色可开启独立会话；开启笔记能力后，模拟指令会真正保存笔记 |
| 版本与重试 | 修改只用于新会话；旧会话保留当时的名称、人设和能力。待确认保存留在 Room，重开继续原 ID/版本/内容 |
| 数据隔离 | 所有者从认证身份取得；他人不可查看、编辑、删除或为私有角色建会话；人设不出现在展示列表 |

新增三个 API 操作，共 16 项：读取所有者定义、PUT 创建/编辑、DELETE 移除。协议由领域接口承载，HTTP 适配、Room 和 Compose 分层；换主题或布局不需要改存储规则。服务端迁移 004 增加所有者、删除标记和版本内名称；手机 Room schema 仍为 2。

## 实现理由和复查

设计取舍记录在 [D29](../decisions.md#d29-先交付私有角色管理修改与删除不改写旧对话)。本次自查及 OpenCodeReview 委托规则核对重点处理了：

1. 旧聊天上下文曾从角色当前资料取名字，允许编辑后会影响旧设定。现在名字和人设、能力一起写入不可变版本，旧会话始终读取版本。
2. 原角色刷新仅追加/更新缓存，服务端删除后本机仍可能显示旧角色。改为完整分页成功后事务替换角色缓存；分页失败保留原缓存，旧聊天不受影响。
3. 未确认创建可能已经成功，并在另一客户端变成更新版本；只允许已有角色重新读取会让它卡在旧版本重试。现在待确认创建也可读取最新已保存版本；若尚未查到创建结果，保留原提交身份与内容。

使用 OpenCodeReview 1.12.12 的 `delegate preview` / `delegate rule`，由 Codex 按 Kotlin、Python、JSON 和通用规则执行审查，没有单独配置模型。默认排除的五份测试文件另行显式取规则复查；生成 OpenAPI 与实际路由、设备摘要与实际输出均核对。范围与规则在忽略目录 `backend/.runtime/ocr-6c/`。结论限本阶段，不代表全仓安全审计。

最终范围 38 个文件：默认可审查 23 个全部覆盖，0 个跳过；另外显式审查 5 个默认排除的测试文件，其余 10 个 Markdown 核对说明与实际行为。最终设备轮次为 `20261005T151552Z`；验收结束后确认专用包只剩截图和非凭证标记，并关闭本轮专用模拟器。

## 限制与下一步

- 回复仍是模拟文本，人设已经存储并进入模型上下文，但未验证真实模型的角色表现；笔记能力有真实工具和数据。
- 角色仅私有，暂未提供头像/背景上传、公开分享、广场和角色搜索。
- 删除保留历史关联，不是数据彻底擦除，也不撤销旧会话权限。未点击保存的角色表单不提供跨进程恢复；点击保存后的待确认提交才持久化。
- 开发身份没有正式注册、登录或账号注销；个人资料功能下一阶段交付，不把这些写成已经实现。
- 6B2 剩余断流/切换/输入法检查仍保留，实体手机、真实 AI 与 MCP 尚未验收。
