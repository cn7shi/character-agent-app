# 阶段 6A：Android 原生基础与本机后端联调

日期：2026 年 10 月 5 日。遵循用户“不等真实 AI、按小阶段继续”的要求，阶段 6 拆成原生基础与事件恢复/设备验收两步。本阶段仍使用后端的固定回复与规则笔记工具。

## 实际交付

- Kotlin/Compose 原生多模块工程与标准 Gradle Wrapper；domain、network 是纯 Kotlin 模块，feature 不直接依赖 Room、HTTP 或供应商。
- 角色列表、最近会话、新会话、聊天、待发送状态、停止回复、笔记与连接设置页面，基础深浅色切换。
- Room schema 1：按连接范围隔离的快照、待发送消息、会话创建请求；消息动作描写与台词保持不同内容块。
- HTTP 后端适配，按原键创建/重试，会话和消息写请求均先保存身份；成功后在 Room 事务中确认，旧任务快照不能覆盖新状态。
- 当前会话每秒查询任务状态，页面退出与应用后台暂停观察，重新进入读取持久任务；SSE 后续实施。
- 后端访问凭证由用户在设置输入，Keystore AES-GCM 加密保存，禁用云备份与设备迁移；模型密钥不进入客户端。
- 本机联调与构建说明、设计决策 D18–D21、可重复执行的 `backend/scripts/check_android.py`。

## 已验证结果

12 项 Android 检查通过、无跳过：

| 检查 | 结果 |
| --- | --- |
| 3 项网络测试 | 请求身份保持、拒绝重定向、取消等待、连接范围隔离和地址限制 |
| 8 项 Room/仓库测试 | 响应丢失后重试、重开数据库、离线读取、连接隔离、内容块保存、旧快照、拒绝与未知受理区分、创建会话去重和取消 |
| 1 项实际 HTTP 联调 | Kotlin HttpTransport → Python FastAPI → 模拟回复/真实笔记 → Room，核对两次聊天、一次笔记、6 条消息、数据库重开与另一用户隔离 |

Room 测试运行于 Robolectric API 34；实际 HTTP 联调使用隔离的临时后端和随机开发凭证，结束后清理服务与数据。没有调用外部 AI 或 MCP。此前后端 57 项测试结果保持在阶段 5 报告，本阶段未修改后端业务代码。

最终源码的 `:app:assembleDebug :app:lintDebug` 通过，调试 APK 已生成。静态检查无错误，仍有依赖/目标 SDK 更新与 KTX 写法建议，不影响当前构建，也没有通过禁用检查或建立基线绕过错误。首次静态检查发现本机路径转义和开发网络配置缺失属性，已修正，并补齐 Android 12 之后的备份/迁移排除规则。取消测试的模拟服务器延迟曾超过其自身清理期限，已调整测试等待窗口，取消检查保留。

## 限制与下一阶段

本机没有连接 Android 设备，也没有可用模拟器；未完成真机 UI、输入法、系统返回、Keystore、旋转与后台恢复验收。不能把 APK 构建和 Robolectric 测试描述为已在手机上跑通。

当前使用任务快照轮询，尚未消费 SSE 与 Last-Event-ID。列表按后端游标读完后缓存，尚未针对大规模历史做分页 UI；草稿仅保存在 ViewModel。没有正式账号、后台自动发送、笔记编辑/删除或完整原型还原。首次连接仍需启动本机后端并填写开发凭证。

下一步阶段 6B 实施 SSE 与持久草稿，取得设备环境后验证用户操作和系统生命周期。阶段 7 再按 HTML 原型完善背景、组件、主题与第二种聊天布局。
